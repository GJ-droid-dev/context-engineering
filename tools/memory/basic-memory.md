# Basic Memory

> The only context tool where the LLM writes back to your files. Truly bi-directional: you talk to the agent, the agent builds a knowledge graph from the conversation, and you can read, edit, and version-control exactly what it learned.

**Source:** [basicmachines-co/basic-memory](https://github.com/basicmachines-co/basic-memory) — 2.7k stars  
**Layer:** 3 — Session & Project Memory  
**WISC:** W + S (agent writes; later retrieves)  
**License:** AGPL-3.0

---

## The Problem It Solves

Most memory tools are one-directional: the developer writes files, the agent reads them. Basic Memory flips this. The agent can write new Observations and Relations back to your knowledge base during conversation — building up project understanding over time without you having to manually document everything.

The result is a knowledge graph that grows with your project, authored collaboratively by you and the agent.

---

## How It Works

Basic Memory stores knowledge as **Entities** (people, components, concepts) with **Observations** (facts about them) and **Relations** (how they connect to each other), all serialized as plain Markdown files.

```markdown
<!-- auto-generated by the agent after a conversation -->
## PaymentService

#payment #service #architecture

### Observations
- Handles Razorpay collection and Cashfree payouts
- Uses asyncHandler wrapper on all controllers
- Settlement queue processes daily at midnight UTC

### Relations
- depends_on: [[PrismaClient]]
- integrates_with: [[RazorpayAPI]]
- triggers: [[SettlementQueue]]
```

The agent can search this graph semantically (hybrid BM25 + vector) to retrieve relevant context for new tasks.

---

## Storage

- **Files:** Plain Markdown, stored in a local directory you specify
- **Database:** SQLite + FTS (full-text search) + hybrid vector index
- **Control:** The files ARE the source of truth — edit them directly and the DB syncs

## Setup

**Install:**
```bash
pip install basic-memory
# or
uvx basic-memory
```

**Initialize a knowledge base:**
```bash
basic-memory init --path ./memory
```

**MCP server config for VS Code:**
```json
// .vscode/mcp.json
{
  "servers": {
    "basic-memory": {
      "command": "uvx",
      "args": ["basic-memory", "mcp", "--path", "./memory"]
    }
  }
}
```

## Key MCP Tools (exposed to the agent)

| Tool | What It Does |
|------|--------------|
| `write_note` | Agent writes a new Markdown note to the knowledge base |
| `read_note` | Agent reads an existing note |
| `search_notes` | Hybrid semantic + keyword search across all notes |
| `create_entities` | Explicitly creates named entities with observations |
| `create_relations` | Links two entities with a typed relation |
| `recent_activity` | Shows what was added or changed recently |

---

## What Makes It Unique

Every other tool in this repo has the agent *reading* from a store that *humans wrote*. Basic Memory is the only tool where the agent *writes* to a store that *humans can read and edit*.

This creates a feedback loop:
1. Developer asks agent a complex question
2. Agent researches, answers, and writes its findings as Observations
3. Developer edits or extends those Observations directly in Markdown
4. Next session, agent loads those notes as starting context

## Limitations

- AGPL-3.0 license — check your project's license compatibility
- Knowledge quality depends on the agent's writing discipline
- Very large knowledge bases may have slower search (optimize with index tuning)

## In This Repo's Architecture

Basic Memory is the **bi-directional memory pattern made concrete**. It sits in Layer 3 alongside ConPort (structured explicit logging) and ICM (session memory). The choice between Basic Memory and ConPort comes down to structure preference: Basic Memory is emergent and flexible; ConPort is explicit and schema-driven.
